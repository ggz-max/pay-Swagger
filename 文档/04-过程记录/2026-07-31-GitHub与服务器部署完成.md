# GitHub 与服务器部署完成

日期：2026-07-31

## 1. 用户要求

- 将完整项目上传至 GitHub 仓库 `https://github.com/ggz-max/pay-Swagger`。
- 通过 `ubuntu@49.232.198.140` 部署到服务器 `/var/www/` 下。
- 延续项目约定，把重要决策、结果和后续操作写入文档。

## 2. 最终部署结构

- 代码：`/var/www/pay-swagger`
- SQLite 数据：`/var/www/pay-swagger-data/production.db`
- API：PM2 进程 `pay-swagger-api`，监听 `127.0.0.1:3200`
- 用户端：`/pay-swagger/`
- 运营台：`/pay-swagger/admin/`
- API 代理：`/pay-swagger/api/`
- Swagger 代理：`/pay-swagger/docs/`
- Nginx 片段：`/etc/nginx/snippets/pay-swagger.conf`

代码、数据与服务器现有 `/var/www/hl-platform` 分离。原 IP 站点只增加一条 include，原有 `/`、`/api/` 和 `/maizeng/` 路由均保留。

## 3. 关键部署决策

1. 服务器系统 Node.js 18 不满足项目 `Node.js >= 22`，因此固定使用 `/opt/node24/bin/node`。
2. API 内部端口使用 3200，避开服务器已有的 3000 和 3100。
3. 前端生产构建使用相对站点前缀和 `/pay-swagger/api/v1`，避免把本地 `127.0.0.1:3000` 写入浏览器包。
4. 首次发布执行 seed，后续发布禁止重复 seed，避免清空演示交易数据。
5. PM2、Nginx、数据库和构建步骤固化在 `deployment/deploy-server.sh`，减少手工发布差异。

## 4. 部署中发现并解决的问题

- `/var/www` 不允许普通用户直接新建目录：先用 sudo 创建精确目标目录，再交给 ubuntu 用户。
- Corepack 可直接运行 pnpm，但子脚本找不到 `pnpm`：部署脚本增加 `corepack enable pnpm`。
- 宿主站点默认首页是 `dashboard.html`：新前端 location 内显式指定 `index index.html`，防止继承宿主配置。
- Nginx 每次修改均先执行 `nginx -t`，通过后才 reload。

## 5. 验收结果

- 用户端、运营台、OAuth 回调页、API 健康检查和 Swagger 均返回 HTTP 200。
- API 只监听 `127.0.0.1:3200`，PM2 状态为 online。
- 用户端生产 JS 从 `/pay-swagger/assets/` 加载成功。
- 本机 Playwright 完成 1440px 用户端、1440px 运营台和 390px 用户端验收。
- 三个浏览器场景均无控制台错误、页面异常或 HTTP 失败请求。
- 截图保存在 `产出/部署截图/`。

## 6. 当前边界

这是公开演示环境，不连接真实支付渠道，不处理真实资金和真实用户数据。当前入口使用服务器 IP 和 HTTP；若用于长期公开展示，应增加域名、HTTPS、访问控制、备份和监控。
