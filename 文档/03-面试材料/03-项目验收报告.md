2026-07-30 最终执行结果：

| 门禁 | 结果 |
|---|---|
| `pnpm typecheck` | 4 个工作区包全部通过 |

端到端覆盖：

1. 桌面/移动正常购买，最终 `FULFILLED/ACTIVE`。
2. 桌面/移动支付成功但权益失败，保持 `PAID/GRANT_FAILED`，不提示重复付款。
3. 桌面/移动运营台发现异常、人工补发，恢复 `FULFILLED/ACTIVE` 并产生审计事件。
4. 桌面/移动 OAuth 授权、PKCE 换 Token、UserInfo 和撤销。
5. 桌面/移动固定视觉截图。

额外 API 验证：

- 相同 `providerEventId` 重放返回 `duplicate=true`。
- OAuth 相同授权码第二次换 Token 返回 HTTP 401。
- 金额不一致事件不改变支付成功状态并产生 S1 异常。

## 4. 已知边界

| 边界 | 原因 | 面试中如何说明 |
|---|---|---|
| 没有真实渠道支付 | 避免真实资金与密钥 | 展示 Provider 边界与通用回调机制 |
| Outbox 同进程处理 | 本地教学简化 | 生产应拆投递器、消息队列和 worker |
| SQLite 单机数据库 | 演示可重复、零依赖 | 生产需评估数据库锁、容灾与扩展 |
| 权益重试未真实等待 4 轮 | 面试需快速复现 | 数据模型保留次数与下次执行时间 |
| OAuth 没有真实登录/MFA | 聚焦协议主链路 | 生产需接账号安全、设备风控和审计 |
| 对账只完成数据模型与契约 | MVP 重点是支付和认证 | 下一阶段接账单导入和差异处理 |
| 订阅只完成模型与 PRD | 一次性购买先闭环 | 后续补续费、扣款失败和宽限期 |
